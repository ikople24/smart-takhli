# สเปค: เล่มพิมพ์บัญชีคุมนิติกรรมรายเดือน (m10 print)

- **วันที่**: 2026-09-21
- **โมดูล**: `m10-ingest` (แผนที่ภาษี ม.10)
- **บราช**: `new-m10`
- **สถานะ**: ผ่านการตกลงกับเจ้าของงานแล้ว รอเขียนแผน implement

## 1. ปัญหาและเป้าหมาย

งานเร่งด่วนของฝ่ายแผนที่ภาษีคือ หลังนำเข้าไฟล์ ม.10 รายเดือนแล้ว ต้อง **พิมพ์เอกสารออกกระดาษเก็บไว้**
เพื่อให้เจ้าหน้าที่รายงานผลว่าเดือนนั้นมีนิติกรรมอะไรบ้าง แล้วใช้กระดาษชุดนั้นเป็นตัวตั้งในการไปปรับข้อมูล
ใน **LTAX Online** อีกทอดหนึ่ง

ปัจจุบันระบบไม่มีอะไรพิมพ์ออกกระดาษได้เลย — แท็บ `Worklist → LTAX` เดินงานบนจอทีละรายการเท่านั้น
และครอบแค่ 4 นิติกรรม (TRANSFER, TRANSFER_PARTIAL, OWNER_CORRECTION, BOUNDARY_CHANGE)

**เป้าหมาย**: หน้าเดียวที่เรนเดอร์ "เล่มรายเดือน" พร้อมสั่งพิมพ์ — ใบปกบัญชีคุม + ใบคั่นหมวด + แผ่นงานรายแปลง

## 2. ขอบเขต

**ทำ**
- หน้าใหม่ `/admin/m10/print?period=YYYY-MM` เรนเดอร์เล่มทั้งเล่ม สั่งพิมพ์ด้วย `window.print()`
- ใบปก = บัญชีคุมนิติกรรมรายเดือน (ตารางนับรายการ + ยอดรวม + ช่องลงนาม)
- ใบคั่นหมวด 1 หน้าต่อหมวด
- แผ่นงานรายแปลง 1 หน้าต่อรายการ สำหรับนิติกรรมที่กระทบภาษีทุกชนิด
- โหมดประหยัดกระดาษ (2 รายการ/หน้า) สำหรับหมวดที่ไม่มีสคริปต์ขั้นตอน
- บันทึก audit ว่าใครสั่งพิมพ์เดือนไหนเมื่อไร

**ไม่ทำ (รอบนี้)**
- สร้างไฟล์ PDF ฝั่งเซิร์ฟเวอร์ (เจ้าหน้าที่ใช้ "Save as PDF" ของเบราว์เซอร์ถ้าต้องการไฟล์)
- export Excel/CSV
- เปลี่ยนสิทธิ์เข้าถึง (ดู §10)
- เขียนสคริปต์ขั้นตอนคีย์ LTAX ให้นิติกรรมที่ยังไม่มี (MERGE/NEW/SPLIT/SPLIT_PUBLIC/RETIRED) —
  แผ่นงานของกลุ่มนี้พิมพ์กล่องว่างให้เจ้าหน้าที่เขียนผลด้วยมือ
- แตะ `ltaxStatus` จากหน้าพิมพ์ (ติ๊กบนกระดาษด้วยมือ แล้วไปกด "คีย์แล้ว" ที่แท็บ worklist เหมือนเดิม)

## 3. การตัดสินใจที่ตกลงแล้ว

| # | ประเด็น | ข้อสรุป |
|---|---|---|
| 1 | รูปเอกสาร | **เล่มรายเดือน** — ใบปกบัญชีคุม + แผ่นงานรายแปลงต่อท้าย (ไม่ใช่ตารางเดียวหรือแผ่นงานล้วน) |
| 2 | ต้องรอกดยืนยันในคิวก่อนพิมพ์ไหม | **ไม่ต้อง** พิมพ์ได้ทันทีหลังอัปโหลด · ทุกแผ่นมีป้ายบอกสถานะ (ยืนยันแล้ว / รอยืนยัน) · คิวยืนยันยังทำหน้าที่เดิมคือสร้างทะเบียน as-of |
| 3 | ขอบเขตแผ่นงาน | **ทุกนิติกรรมที่ `taxRelevant === true`** (เดือน 2569-01 = 63 จาก 87) · ที่ไม่กระทบภาษี (จำนอง/หมายเหตุ/ใบแทน) ขึ้นเฉพาะบัญชีคุม ไม่มีแผ่นงาน |
| 4 | การแยกคัด | **ชั้นบน = ชนิดเอกสารสิทธิ** (โฉนด → สิ่งปลูกสร้าง → น.ส.3ก เพราะคีย์คนละทะเบียนใน LTAX) **ชั้นใน = หมวดนิติกรรม** มีใบคั่นทุกหมวด · ในหมวดเรียงตามวันที่จดทะเบียน |
| 5 | PDPA บนกระดาษ | **พิมพ์เลข 13 หลักเต็มทั้งเล่ม** ทั้งใบปกและแผ่นงาน เพื่อให้คีย์ LTAX สะดวกและให้เจ้าหน้าที่ดูเอกสารได้ · ขอบเขตนี้**เฉพาะเอกสารชุดนี้** — ที่อื่นในระบบคงกติกาเดิม (`owner.idHash`, เลขดิบส่งเฉพาะ endpoint focus, ไม่ log) · safeguard: บรรทัดท้ายแผ่น "เอกสารใช้ในราชการ — มีข้อมูลส่วนบุคคล" + audit log ทุกครั้งที่สั่งพิมพ์ |
| 6 | วิธีทำ | **print CSS ในเบราว์เซอร์** (ไม่ใช่ PDF ฝั่งเซิร์ฟเวอร์, ไม่ใช่ Excel) — ฟอนต์ไทยไม่มีปัญหา ไม่เพิ่ม dependency เจ้าหน้าที่ดูบนจอได้ทันทีโดยไม่ต้องสร้างไฟล์ |

รวม **11 ใบคั่น · 63 แผ่นงาน** (มีสคริปต์ 33 · กล่องว่าง 30)
ส่วนที่ไม่กระทบภาษีซึ่งขึ้นเฉพาะบัญชีคุม: โฉนด—จำนอง/ไถ่ถอน 16 · โฉนด—หมายเหตุ 3 · โฉนด—ใบแทน 1 ·
สิ่งปลูกสร้าง—จำนอง 3 · สิ่งปลูกสร้าง—หมายเหตุ 1 = 24 รายการ

**หมวดที่ไม่มีรายการในเดือนนั้น ไม่พิมพ์ใบคั่น** (ไม่มีหน้าเปล่า) — สังเกตว่างวดนี้ `RETIRED` อยู่ใต้
น.ส.3ก ไม่ใช่โฉนด ดังนั้น**ห้าม hardcode ว่าหมวดไหนอยู่ใต้ชนิดเอกสารไหน** ต้องประกอบจากข้อมูลจริง

### ลำดับหมวดคงที่ (`labels.ts`)

`docType`: `PARCEL` → `CONSTRUCTION` → `NS3A`

`changeType` ที่กระทบภาษี (ลำดับนี้):
`TRANSFER` → `TRANSFER_PARTIAL` → `MERGE` → `NEW` → `SPLIT` → `SPLIT_PUBLIC` → `BOUNDARY_CHANGE` → `RETIRED` → `OWNER_CORRECTION`

ที่ไม่กระทบภาษี (ขึ้นบัญชีคุมเท่านั้น ไม่มีใบคั่น/แผ่นงาน): `ENCUMBRANCE`, `NOTE`, `ADMIN`

### ชื่อไทยที่ใช้แสดง

| ค่า | ป้ายบนกระดาษ |
|---|---|
| `PARCEL` | โฉนดที่ดิน |
| `CONSTRUCTION` | สิ่งปลูกสร้าง |
| `NS3A` | น.ส.3ก |
| `TRANSFER` | โอนกรรมสิทธิ์ |
| `TRANSFER_PARTIAL` | ให้เฉพาะส่วน |
| `MERGE` | รวมโฉนด |
| `NEW` | เอกสารสิทธิเกิดใหม่ |
| `SPLIT` | แบ่งแยกในนามเดิม |
| `SPLIT_PUBLIC` | แบ่งหักเป็นที่สาธารณประโยชน์ |
| `BOUNDARY_CHANGE` | สอบเขตโฉนดที่ดิน |
| `RETIRED` | ยกเลิกเอกสารสิทธิ |
| `OWNER_CORRECTION` | แก้ชื่อเจ้าของ |
| `ENCUMBRANCE` | จำนอง/ไถ่ถอน (ไม่กระทบภาษี) |
| `NOTE` | หมายเหตุสารบัญ (ไม่กระทบภาษี) |
| `ADMIN` | ใบแทน (ไม่กระทบภาษี) |

**สำคัญ:** ป้ายหมวดคือชื่อกลุ่ม แต่**ชื่อนิติกรรมรายรายการต้องใช้ `rawStatus` ดิบจากกรมที่ดิน**
(เช่น "ขายตามคำสั่งศาล", "ไถ่ถอนจากจำนอง รวมสองโฉนด") ทั้งในบัญชีคุมและหัวแผ่นงาน —
เพราะนี่คือถ้อยคำที่เจ้าหน้าที่ใช้รายงานและตรวจทานกับเอกสารต้นฉบับ

### ใบปก = บัญชีคุม

- หัวกระดาษ: "เทศบาลเมืองตาคลี" / "บัญชีคุมนิติกรรมที่ดินและสิ่งปลูกสร้าง" / "ประจำเดือน &lt;เดือนไทย พ.ศ.&gt;"
- บรรทัดรอง: งวดข้อมูล (`period`) · วันที่พิมพ์ · ผู้สั่งพิมพ์ · จำนวน batch ที่นำเข้าในงวดนี้
- ตารางนับรายการ 1 แถวต่อ (ชนิดเอกสาร × `rawStatus`) คอลัมน์:
  ชนิดเอกสาร · ชื่อนิติกรรม (`rawStatus`) · หมวด · กระทบภาษี (✓/—) · จำนวน · คีย์แล้ว · ค้างคีย์
- ยอดรวมท้ายตาราง: รายการทั้งหมด · กระทบภาษี · ไม่กระทบภาษี · จำนวนแผ่นงานในเล่ม
- ช่องลงนาม 3 ช่อง: ผู้จัดทำ / หัวหน้าฝ่ายแผนที่ภาษีและทะเบียนทรัพย์สิน / ผู้อำนวยการกองคลัง

### แผ่นงานรายแปลง (5 บล็อก)

1. **หัวแผ่น** — ลำดับในหมวด (x/n) · ลำดับในเล่ม · ชื่อนิติกรรม (`rawStatus`) · วันที่จดทะเบียน ·
   ชนิดเอกสาร · ป้ายสถานะยืนยัน
2. **ข้อมูลยืนยันแปลง** — เลขโฉนด · `PARCEL_COD` (หรือ "ยังไม่จับคู่") · ระวาง 4 ช่อง + มาตราส่วน ·
   เลขที่ดิน · หน้าสำรวจ · เนื้อที่ ไร่-งาน-วา
3. **เจ้าของ** — คำนำหน้า/ชื่อ/นามสกุล · **เลข 13 หลักเต็ม (เลขล้วน ไม่มีขีด)** · ที่อยู่ครบ · โทรศัพท์ ·
   เจ้าของเดิม (เฉพาะ `TRANSFER`) · ราคาจดทะเบียน (ถ้ามี)
4. **ขั้นตอนคีย์ LTAX** — 4 นิติกรรมที่มีสคริปต์: พิมพ์ `steps` จาก `buildWorklistItem()` เดิม ·
   นิติกรรมอื่น: กล่องว่างหัวว่า "ผลการดำเนินการ" สูงพอเขียน 4–5 บรรทัด
5. **ท้ายแผ่น** — ☐ คีย์ LTAX แล้ว · ผู้คีย์ ______ · วันที่ ______ · หมายเหตุ ______ ·
   บรรทัดเล็ก "เอกสารใช้ในราชการ — มีข้อมูลส่วนบุคคล"

## 5. ที่มาของข้อมูลทุกฟิลด์

**หลักการ:** `owner` ใน `m10_transactions` เก็บแค่ `idHash` — **ไม่มีเลขบัตรดิบ** เลข 13 หลักและที่อยู่
อยู่ใน `payloadRaw` เท่านั้น เหมือนที่ `buildWorklistItem` ทำอยู่

| ฟิลด์บนกระดาษ | ที่มา |
|---|---|
| ชื่อนิติกรรม | `txn.rawStatus` |
| หมวด / กระทบภาษี | `txn.changeType` / `txn.taxRelevant` |
| ชนิดเอกสาร | `txn.docType` |
| วันที่จดทะเบียน | `txn.txnDate` → `formatThaiDate()` (**Asia/Bangkok บังคับ**) |
| สถานะยืนยัน | `txn.reviewStatus` (`confirmed` → "ยืนยันแล้ว" · `auto`/`pending` → "รอยืนยัน") |
| คีย์แล้ว/ค้างคีย์ (ใบปก) | `txn.ltaxStatus` (`keyed` = คีย์แล้ว · `skipped` = ข้าม · อื่น = ค้าง) |
| เลขโฉนด | `txn.deedNo` |
| `PARCEL_COD` | `m10_records` ที่ `recordKey` ตรงกัน: `reconcileOverride.parcelCode ?? parcelCode ?? null` |
| ระวาง / มาตราส่วน | `payloadRaw.UTM_MAP1` · `UTM_MAP2` → เลขโรมัน (1→I…4→IV) · `UTM_MAP3` · `UTM_MAP4` → pad 2 หลัก · `UTM_SCALE` |
| เลขที่ดิน / หน้าสำรวจ | `payloadRaw["ที่ดิน"]` · `payloadRaw["ห.สำรวจ"]` |
| เนื้อที่ | `txn.area.rai` / `.ngan` / `.wa` (ทศนิยม 2 ตำแหน่ง) |
| ชื่อเจ้าของ | `payloadRaw["คำนำหน้า"]` · `["ชื่อ"]` · `["นามสกุล"]` |
| เลข 13 หลัก | `payloadRaw["13 หลัก"]` → ตัดอักขระที่ไม่ใช่เลขออก |
| ที่อยู่เจ้าของ | `OWN_HSE_NO` · `OWN_MOO` · `OWN_SOI` · `OWN_VILLAGE` · `OWN_ROAD` · `OWN_TAMBOL` · `OWN_AMPHUR` · `OWN_PROVINCE` · `OWN_TEL` |
| เจ้าของเดิม | เหมือนที่ worklist ใช้อยู่ (ชื่อเจ้าของบน `m10_records` ก่อน apply txn) |
| ราคาจดทะเบียน | `txn.regAmount` (null → ไม่พิมพ์บรรทัดนี้) |
| ขั้นตอนคีย์ | `buildWorklistItem(txn, oldOwnerName, period).steps` — **เรียกของเดิม ห้ามก็อป logic** |

การเรียงในหมวด: `txnDate` ขึ้น แล้ว tie-break ด้วย `deedNo` แล้ว `recordKey` (ให้ผลคงที่ พิมพ์ซ้ำได้เหมือนเดิม)

## 10. สิทธิ์เข้าถึง (ตัดสินใจแล้วว่าไม่แตะรอบนี้)

หน้าใหม่อยู่ใต้ `/admin/m10/print` จึงได้สิทธิ์ตาม prefix ของ `/admin/m10` อัตโนมัติ
(`pathMatchesPermission` = exact หรือ prefix + `/`) — **ไม่ต้องรัน migration** เหมือนตอนเพิ่มหน้า basemap

**ข้อเท็จจริงที่ต้องรู้:** เจ้าของงานระบุว่าเอกสารนี้ควรเป็น "ระบบปิดสำหรับเจ้าหน้าที่เฉพาะทาง"
แต่สภาพจริงวันนี้คือ `/admin/m10` **อยู่ใน `DEFAULT_PERMISSIONS.admin`** = admin ที่ไม่ได้ตั้ง
`allowedPages` เองเข้าได้ทุกคน และแท็บ worklist ที่มีอยู่แล้ว**ก็แสดงเลข 13 หลักพร้อมปุ่มคัดลอกอยู่**
→ หน้าพิมพ์นี้ไม่ได้เปิดข้อมูลเพิ่มจากที่เปิดอยู่เดิม จึงไม่แตะสิทธิ์ในรอบนี้เพื่อไม่ให้ของเดิมพัง

ถ้าต้องการปิดจริงต้องแยกเป็นงานอีกชิ้น: ตั้ง path นอก prefix เดิม (เช่น `/admin/m10-print`)
ลงทะเบียนใน `ALL_PAGES` แต่**ไม่ใส่ใน `DEFAULT_PERMISSIONS`** ให้ superadmin ติ๊กรายคน
(pattern เดียวกับ `/admin/smart-water`) + เพิ่มเมนูใน `LayoutAdmin.tsx` + grant script

## 11. ความเสี่ยงและเรื่องค้าง

- **ปริมาณกระดาษ** — งวด 2569-01 = ใบปก 2 + ใบคั่น 11 + แผ่นงาน 63 = **76 หน้า/เดือน**
  โหมดประหยัดกระดาษลดได้เฉพาะ 30 แผ่นที่เป็นกล่องว่าง (เหลือ ~15 หน้า) → ประมาณ **61 หน้า**
- **page-break ต้องเทสต์กับเครื่องพิมพ์จริง 1 รอบ** — พรีวิวในเบราว์เซอร์กับผลพิมพ์จริงมักไม่ตรงเป๊ะ
  โดยเฉพาะแผ่นงานที่ `steps` ยาว
- **หน่วย `เศษ`** ยังเป็น open item เดิมของโมดูล (ต้องยืนยันกับ LTAX 1 รายการก่อน production)
  รอบนี้แผ่นงานพิมพ์ ไร่-งาน-วา จาก `txn.area` ที่ normalize แล้ว — **ยังไม่พิมพ์ค่าดิบ `เศษ` กำกับ**
  ถ้าเจ้าหน้าที่ต้องการตรวจทานค่าดิบ ค่อยเพิ่มภายหลัง
- **re-import period เดิม** จะมีหลาย batch ใน period เดียว รอบนี้พิมพ์ทุก txn ของทุก batch และ
  แสดง `batchCount` บนใบปกให้เห็น ถ้าเจอรายการซ้ำเจ้าหน้าที่จะสังเกตได้จากตัวเลขนี้ —
  ยังไม่ทำ dedup ข้าม batch
- **เลข 13 หลักเต็มบนกระดาษ** เป็นการตัดสินใจของเจ้าของงานโดยรู้ข้อแลกเปลี่ยนแล้ว (§3 ข้อ 5)
  safeguard ที่มีคือบรรทัดกำกับท้ายแผ่น + audit log เท่านั้น ตัวกระดาษเองไม่มีการควบคุม
- **นิติกรรม 5 ชนิดยังไม่มีสคริปต์ขั้นตอน** (MERGE/NEW/SPLIT/SPLIT_PUBLIC/RETIRED = 30 รายการใน
  เดือนนี้) เจ้าหน้าที่ต้องเขียนผลด้วยมือ ถ้าอยากได้สคริปต์ต้องทำรอบถัดไปพร้อมเอนจิน Parcel Code
