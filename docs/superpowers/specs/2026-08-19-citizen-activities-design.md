# ดีไซน์เฟส 4: ข่าว & กิจกรรมโฉมใหม่ (`/preview/activities`)

วันที่: 2026-08-19 · สถานะ: อนุมัติแนวทางแล้ว (เจ้าของสั่ง "ไปเฟสถัดไป") · ภาพอ้างอิง:
แคนวาสจอ "ข่าว & กิจกรรม" (`:338-378` — หัวย้อนกลับ ไม่มี Nav ล่าง ตามที่แก้รอบตัดแท็บ)

## สรุป

หน้าเดียว `/preview/activities` สองมุมมอง: **ฟีด** (การ์дเด่น + ลิสต์) และ
**รายละเอียด** (`?activity=<id>` — ลิงก์แชร์ได้ เหมือนกลไกหน้าเดิม) — หน้าเก่า
`/activities` ไม่แตะ

## ข้อเท็จจริงข้อมูล (สำรวจแล้ว)

- `GET /api/activities/feed?limit=..` (เพดาน 50) → `{success, data:[{_id, name,
  description, startDate, endDate, images[≤6], views}]}` เรียง startDate ใหม่→เก่า
  ไม่มีแบ่งหน้า/กรองฝั่ง server → ดึง 50 แล้วกรองฝั่ง client
- **ไม่มีฟิลด์หมวด** — chips "กิจกรรม/ประกาศ/จัดซื้อจัดจ้าง" ในแคนวาสเป็น
  placeholder → ใช้ **chips ตามช่วงเวลา** (ข้อมูลจริง): ทั้งหมด · กำลังจะเริ่ม ·
  กำลังดำเนินการ · สิ้นสุดแล้ว — เกณฑ์เดียวกับ `getActivityStatus` ของหน้าเดิม
  (`now < startDate` = กำลังจะเริ่ม · `now > endDate` = สิ้นสุดแล้ว · ระหว่างนั้น =
  กำลังดำเนินการ)
- เปิดรายละเอียด → `POST /api/activities/<id>/view` (ตัวนับเดิม — พฤติกรรมเดียว
  กับหน้าเก่า)

## ฟีด

หัวย้อนกลับ (โครงเดียวกับจอสถานะ) + chips · **การ์ดเด่น** = รายการแรกที่มีรูป
(รูปใหญ่ + badge สถานะ + ชื่อ + คำอธิบาย 2 บรรทัด + วันที่) · ที่เหลือ = การ์ดแถว
(รูปย่อ 74px + ชื่อ + วันที่ไทย + ยอดอ่าน + ชิปสถานะเล็ก) · ว่าง = empty state

## รายละเอียด (`?activity=`)

แกลเลอรีรูปเลื่อนแนวนอน (≤6) · ชื่อ + ชิปสถานะ (จุดเขียว pulse เมื่อกำลังดำเนิน) ·
ช่วงวันที่ไทย (เริ่ม–สิ้นสุด) · ยอดอ่าน · คำอธิบาย (pre-line) · ปุ่มแชร์ (Web
Share/copy — แบบจอสถานะ) · back → ฟีด (ลบ query)

## Logic ล้วน + เทสต์

`lib/citizen/activities/phase.js` — `activityPhase(activity, now)` →
`{key: upcoming|active|ended, label, chipBg, chipText, dot}` (รับ `now` เป็น
พารามิเตอร์ เทสต์ได้ ไม่พึ่งเวลาเครื่อง) · สี: กำลังจะเริ่ม=เหลือง ·
กำลังดำเนินการ=เขียว · สิ้นสุดแล้ว=เทากลาง (ป้ายคำตรงหน้าเดิม)

## เดินสาย

`NewsSection` หน้าแรก: "ดูทั้งหมด ›" → `/preview/activities` · การ์ดข่าว →
`/preview/activities?activity=<id>` (เลิกชี้หน้าเก่า)

## การทดสอบ

vitest: activityPhase ทุกช่วง+ขอบ · UI: ภาพแคปฟีด/กรอง/รายละเอียด ด้วยข้อมูลจริง ·
e2e intercept `POST /view` กันสถิติปลอมจากการทดสอบ

เสนอเป็นงานฝั่ง admin ภายหลัง) · โปรไฟล์ (เฟส 5)
