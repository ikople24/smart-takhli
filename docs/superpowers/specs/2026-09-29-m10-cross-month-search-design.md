# m10: ค้นหานิติกรรมข้ามเดือน (สำหรับตรวจสอบย้อนหลัง)

Status: approved (brainstorming), pending implementation plan
Date: 2026-09-29

## ปัญหา

โมดูล `m10-ingest` (นำเข้า/normalize ข้อมูลมาตรา 10 จากกรมที่ดิน) ยังไม่มีวิธีค้นหานิติกรรมของแปลงใดแปลงหนึ่งย้อนหลังข้ามหลายเดือน เมื่อต้องตรวจสอบเหตุการณ์ในอดีต (เช่น ตรวจสอบว่าค่าที่ระบบคำนวณตรงกับข้อมูลดิบไหม) เจ้าหน้าที่/ผู้ดูแลต้องรู้เดือนที่ต้องการล่วงหน้าแล้วเปิดเล่มพิมพ์ (`/admin/m10/print`) หรือให้ผู้พัฒนา query MongoDB ตรง — ไม่มีทางค้นแบบ "รู้แค่เลขโฉนด/ชื่อเจ้าของ แล้วหาว่าอยู่เดือนไหน"

หน้าที่ใกล้เคียงที่มีอยู่แล้วใช้แทนกันไม่ได้:
- **ทะเบียน (as-of)** (`components/m10/RecordsPanel.jsx` + `GET /api/m10-ingest/records`) — แสดงแค่ **สถานะปัจจุบัน** ของแปลง ไม่มีช่องค้นหา ถ้าแปลงถูกแก้หลายครั้งจะเห็นแต่ค่าล่าสุด ประวัติเดือนเก่าถูกทับ
- **เล่มพิมพ์รายเดือน** (`lib/m10-ingest/repository/index.ts#listPrintRows` + `lib/m10-ingest/print/buildBook.ts`) — ต้องเลือกเดือนก่อนถึงจะดูได้ และจัดโครงสร้างเป็นหมวด/แผ่นงานสำหรับพิมพ์ ไม่เหมาะเป็นตารางค้นหา

## แนวทางที่พิจารณา

1. **แท็บใหม่ "ค้นหา" query ตรงจาก `m10_transactions` ข้ามทุกงวด (เลือกแนวทางนี้)** — ค้น server-side ข้าม `deedNo` / `payloadRaw.LAND_NO` / `owner.fullName` / `parcelCode` (join จาก `M10Record`) ไม่จำกัดช่วงเวลา
2. ต่อยอดจากหน้าพิมพ์เล่ม — ตัดทิ้งเพราะโครงสร้างข้อมูลถูกจัดกลุ่มเป็นหมวด/แผ่นงานเพื่อพิมพ์ ไม่เหมาะเป็นตารางค้นหาแบบแบน แถมยังต้องรู้เดือนก่อนอยู่ดี
3. เพิ่มช่องค้นหาในแท็บทะเบียน (as-of) เดิม — ตัดทิ้งเพราะ as-of โชว์แค่สถานะปัจจุบัน ไม่ตอบโจทย์ "เห็นทุกนิติกรรมที่เคยเกิด"

## UX

เพิ่มแท็บ **"ค้นหา"** ใน `/admin/m10` ต่อจากแท็บที่มีอยู่ (สรุปรายเดือน · นำเข้า · คิวยืนยัน · ทะเบียน · จับคู่ basemap · Worklist→LTAX)

- ช่องค้นหาเดียว (ตามรูปแบบเดิมของแท็บคิวยืนยัน) — พิมพ์เลขโฉนด/เลขที่ดิน/ชื่อเจ้าของ (คนแรก)/รหัสแปลง LTAX ได้ในช่องเดียว ต้องพิมพ์อย่างน้อย 2 ตัวอักษรถึงเริ่มค้น
- ผลลัพธ์ = ตาราง 1 แถวต่อ 1 นิติกรรม เรียงจากล่าสุด→เก่า คอลัมน์: งวด/วันที่ · ประเภทเอกสาร · นิติกรรม · เลขโฉนด/เลขที่ดิน · เจ้าของ · เนื้อที่ · สถานะยืนยัน · สถานะคีย์ LTAX
- แบ่งหน้า 20 แถว/หน้า (ปุ่ม "โหลดเพิ่ม" แบบเดียวกับคิวยืนยัน)
- คลิกแถว → modal รายละเอียดเต็ม: payloadRaw ดิบทั้งก้อน (รวม `OWN_PERS_ID` — หน้านี้อยู่หลัง `requireM10Admin` เหมือนหน้าพิมพ์เล่มที่โชว์แบบเดียวกันอยู่แล้ว) · เจ้าของร่วม (coOwnerRows) ถ้ามี · เนื้อที่ไร่-งาน-วา (ใช้ `formatRaiNganWa` เดิม ไม่คำนวณซ้ำ) · ใครยืนยัน/เมื่อไหร่ · ใครคีย์ LTAX/เมื่อไหร่/หมายเหตุ · รหัสแปลง

ไม่กรองตาม `reviewStatus` — เห็นทั้ง pending/confirmed/rejected/auto เพราะเป็นเครื่องมือตรวจสอบย้อนหลัง ต้องเห็นครบ (หลักการเดียวกับเล่มพิมพ์ที่ยึดอยู่แล้ว — ดู `print.test.ts` "คืนทุก txn ของงวดนั้น ไม่กรองตาม reviewStatus")

## Backend

**Repository function ใหม่** `searchM10Transactions(q, opts: {skip, limit})` ใน `lib/m10-ingest/repository/index.ts` (รูปแบบเดียวกับ `listPrintRows` ที่มีอยู่แล้ว):

1. escape อักขระ regex พิเศษในคำค้น แล้วสร้าง `RegExp(q, "i")` (ค้นแบบ contains ไม่ต้องพิมพ์เป๊ะ)
2. หา `recordKey` ที่ `M10Record.parcelCode` หรือ `M10Record.reconcileOverride.parcelCode` ตรงกับคำค้นก่อน (parcelCode ไม่ได้เก็บอยู่ใน transaction ตรง ๆ)
3. Query `M10Transaction` ด้วย `$or`: `deedNo` regex · `payloadRaw.LAND_NO` regex · `owner.fullName` regex · `recordKey ∈ (ผลจากข้อ 2)`
4. เรียงตาม `txnDate` ใหม่→เก่า, `skip`/`limit` (default limit 20)
5. เติม `period` (join จาก `M10ImportBatch`) และ `parcelCode` ปัจจุบัน (join จาก `M10Record`) ให้ทุกแถวผลลัพธ์ — ใช้วิธี join เดียวกับที่ `listPrintRows` ทำอยู่แล้ว

**API:** `GET /api/m10-ingest/search?q=...&skip=...` — gate ด้วย `requireM10Admin` เหมือนทุก endpoint ในโมดูลนี้ ปฏิเสธ `q` สั้นกว่า 2 ตัวอักษร (400)

### ขอบเขตที่ตั้งใจตัดออกจาก v1 นี้

- **ค้นหาชื่อเจ้าของร่วม (คนที่ 2 เป็นต้นไปใน `coOwnerRows`) ยังไม่รองรับ** — ค้นได้เฉพาะเจ้าของคนแรก (`owner.fullName`) เท่านั้น เพราะ `coOwnerRows` เป็น raw payload แยกฟิลด์ชื่อ-นามสกุล ไม่ได้ต่อเป็น fullName พร้อมค้น ต้องเพิ่ม `$elemMatch` ซับซ้อนขึ้น — เก็บเป็นรายการขยายทีหลังถ้าเจอว่าจำเป็นจริงจากการใช้งาน
- ไม่เพิ่ม text index ให้ `owner.fullName` / `payloadRaw.LAND_NO` ตอนนี้ — ที่ขนาดข้อมูลปัจจุบัน (~1,200 แถว โตประมาณ 150/เดือน) regex scan เร็วพอ ไม่คุ้มเพิ่ม infra search ก่อนเจอปัญหาจริง

## Testing

`lib/m10-ingest/repository/search.test.ts` (ใช้ `mongodb-memory-server` แบบเดียวกับ `print.test.ts`):

- ค้นเจอด้วยแต่ละฟิลด์แยกกัน: `deedNo`, `payloadRaw.LAND_NO`, `owner.fullName`, `parcelCode` (ผ่าน `M10Record`)
- ผลลัพธ์ข้ามงวดรวมกันเรียงตามวันที่ถูกต้อง (สร้าง txn 2 งวดคนละเดือน ค้นแล้วต้องเจอทั้งคู่)
- แบ่งหน้าทำงาน (`skip`/`limit` ตัดถูกจำนวน)
- ไม่พบ → คืน array ว่าง ไม่ throw
- คำค้นที่มีอักขระ regex พิเศษ (เช่น `.`, `*`) ไม่ทำให้ query error หรือ match ผิดเพี้ยน
- API layer: `q` สั้นกว่า 2 ตัว → 400
