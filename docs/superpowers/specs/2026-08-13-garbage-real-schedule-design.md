## หัวใจของงานนี้: ต้องแยกสามสถานะ ไม่ใช่สอง

ข้อมูลจริงบังคับให้แยกสถานะของจุดในแต่ละวันเป็น **สาม** แบบ ขณะที่โมเดลเดิมมีแค่สอง:

| สถานะ | ตัวอย่าง | โมเดลเดิมทำได้ไหม |
|---|---|---|
| เก็บ และรู้เวลา | ถนนดอกไม้แดง วันจันทร์ 4.00 น. | ได้ |
| **วันนี้ไม่เก็บ** | ถนนดอกไม้แดง วันอังคาร | **ไม่ได้** — แสดงเป็น "—" เหมือนกรณีถัดไป |
| **เก็บ แต่ยังไม่ระบุเวลา** | ทุกจุดของรถ 13 | **ไม่ได้** |

โมเดลเดิมมี `atMin` ว่างค่าเดียวสื่อทั้งสองความหมาย → ชาวบ้านอ่านว่า "มาเก็บแต่ไม่รู้เวลา" ทั้งที่ความจริงอาจคือ "วันนี้ไม่มา" ซึ่งเป็นข้อมูลผิด

### วิธีแก้: `stopTimes` = รายการจุดที่เก็บวันนั้น โดยเวลาเป็นค่าว่างได้

เปลี่ยน `StopTime.atMin` จาก `Minutes` เป็น `Minutes | null` แล้วให้ความหมายเป็น:

- **จุดอยู่ใน `stopTimes` และมี `atMin`** → เก็บ เวลานี้
- **จุดอยู่ใน `stopTimes` แต่ `atMin` เป็น null** → เก็บ แต่ยังไม่ระบุเวลา
- **จุดไม่อยู่ใน `stopTimes`** → วันนี้ไม่เก็บ

เป็นการเปลี่ยนที่เล็กที่สุดที่รองรับข้อมูลจริงได้ครบ และไม่ต้องเพิ่มฟิลด์ใหม่ในสคีมา

**ผลกระทบที่ต้องแก้ตามกัน:**

1. `types/garbage.ts` — `StopTime.atMin: Minutes | null` และ `ResolvedAssignment.stops[]` เพิ่มธง `served: boolean`
2. `lib/garbage/resolve.ts#buildDaySchedule` — เดิม map ทุกจุดของสายพร้อม `atMin` จาก `timeBySeq` · ใหม่ต้องแยก `served` (มีคีย์ใน `stopTimes` หรือไม่) ออกจาก `atMin` (ค่าที่ได้)
3. `lib/garbage/validators.ts` — refine "เวลาใน stopTimes ต้องไม่ย้อนกลับ" ต้อง**ข้าม** entry ที่ `atMin` เป็น null (ไม่งั้นรถ 13 บันทึกไม่ได้)
4. `lib/garbage/live.ts` — `getLivePosition` กรอง `s.atMin != null` อยู่แล้ว จึงไม่พัง แต่ควรกรอง `served` ด้วยเพื่อไม่ให้จุดที่วันนี้ไม่เก็บถูกนับ
5. `pages/api/garbage/search.ts` — ผลค้นหาต้องไม่บอกว่า "เก็บวันนี้" สำหรับจุดที่ `served` เป็น false · ต้องเพิ่ม `served` ใน `SearchHit` และให้หน้าเว็บแสดงต่างกัน
6. **หน้าประชาชน** — จุดที่ไม่เก็บวันนั้นแสดงแบบจาง/ขีดฆ่า พร้อมคำว่า "วันนี้ไม่เก็บ" · จุดที่เก็บแต่ไม่มีเวลาแสดง "ยังไม่ระบุเวลา" (ต่างจาก "—" เฉย ๆ)
7. **หน้าแอดมิน** — `StopTimesEditor` ต้องมีช่องติ๊ก "เก็บวันนี้" ต่อจุด แยกจากช่องกรอกเวลา และแก้ข้อความช่วยเดิมที่บอกว่า "เว้นว่างได้ถ้ายังไม่ทราบเวลา" ให้ตรงความหมายใหม่

## สคริปต์นำเข้า

`scripts/import-garbage-schedule.mjs` — อ่าน `data/garbage/schedule-2569.json` (+ `trucks.local.json` ถ้ามี) แล้วเขียนลง DB

**ต้องเป็นการ re-baseline อย่างจงใจ ไม่ใช่ upsert เงียบ ๆ** เพราะ M6 กำหนดให้ UI เป็นแหล่งความจริงแล้ว การเขียนทับข้อมูลที่เจ้าหน้าที่แก้ไว้ต้องเป็นสิ่งที่สั่งชัดเจน:

- ไม่ใส่แฟล็ก = dry-run แสดงว่าจะเปลี่ยนอะไรบ้าง (เพิ่ม/ทับ/ลบกี่รายการ)
- `--yes` = เขียนจริง
- ถ้าพบว่ามี assignment ที่ `updatedAt` ใหม่กว่า `createdAt` อย่างชัดเจน (= เคยถูกแก้จาก UI) ให้เตือนและ**ต้องใส่ `--force` เพิ่ม** จึงจะทับ
- เขียน audit log หนึ่งรายการสรุปการนำเข้า (action ใหม่ `garbage_schedule_imported`, resourceType `system`) เพื่อให้ย้อนดูได้ว่าใครนำเข้าเมื่อไร — สคริปต์รันจาก command line จึงใช้ `actorClerkId: "script"` พร้อม `meta` บอกจำนวน

**การแมปข้อมูล:**

- **สาย**: รถเบอร์ N → สาย `R{N}` ชื่อ "สาย R{N}" · `stops` = จุดทั้งหมดของรถคันนั้นเรียงตามลำดับในไฟล์ · `defaultTruckNumber: N` · `needsVerification: false` (ข้อมูลจากกองสาธารณสุขโดยตรง = ปลดป้าย "รอตรวจสอบ" ของ R5–R7 ได้เลย)
- **งานมอบหมาย**: (วัน, รถ N, รอบ 1) สำหรับทุกวันที่รถคันนั้นมีจุดเก็บ · `stopTimes` = จุดที่มีเวลาวันนั้น · `startMin`/`endMin` = เวลาน้อยสุด/มากสุดของวันนั้น
- **วันหยุด**: วันที่รถคันนั้นไม่มีจุดเลย → `kind: "day_off"`, `label: "วันหยุด"`, ไม่มีเวลา
- **แทนเบอร์**: หมายเหตุ "เก็บแทนเบอร์ X" ในแถวของวันไหน → วันนั้นสร้างงานเพิ่มอีกหนึ่งรอบ `kind: "substitute"`, `coverForRouteCode: "R{X}"` โดยแยกจุดที่มีหมายเหตุนั้นออกมาเป็นงานคนละรอบกับงานปกติ (เพราะเป็นการวิ่งแทนสายอื่น ไม่ใช่สายตัวเอง) — **ต้องยืนยันว่าเวลาไม่ทับกับรอบปกติของรถคันเดียวกัน** ด้วย `findOverlap` ก่อนเขียน
- **รถ 13**: สาย `R13` ชื่อ "สาย R13 (รถยกภาชนะรองรับ)" · งานของแต่ละวันมี `stopTimes` = จุดที่เก็บวันนั้น **ทุกตัว `atMin: null`** และ `startMin`/`endMin` เป็น null → `kind` ต้องเป็น `"special"` เพราะ validator บังคับว่า `normal` ต้องมีเวลา
- **ทะเบียนรถ**: `garbage_trucks` เพิ่มฟิลด์ `plate`, `driverName`, `truckType` จาก `trucks.local.json` (ถ้าไฟล์ไม่มีให้ข้ามพร้อมแจ้ง ไม่ล้มทั้งสคริปต์ — เครื่อง deploy ไม่มีไฟล์นี้)

## ข้อมูลพนักงานกับการแสดงผล

`driverName` เป็นข้อมูลพนักงาน — **แสดงเฉพาะหน้าแอดมิน ห้ามส่งออก API สาธารณะ** (`/api/garbage/{schedule,week,search,live}`) · ต้องเช็คว่า `Truck` ถูกส่งออกทาง API สาธารณะตรงไหนบ้างก่อนเพิ่มฟิลด์ · `plate` และ `truckType` ไม่ใช่ข้อมูลส่วนบุคคล เปิดได้

## ความเสี่ยง

1. **นำเข้าแล้วทับข้อมูลที่แก้จาก UI** — บรรเทาด้วย dry-run เป็นค่าตั้งต้น + ต้อง `--force` เมื่อพบร่องรอยการแก้จาก UI + audit log
2. **การเปลี่ยนความหมายของ `atMin` กระทบทุกชั้น** — ถ้าแก้ไม่ครบจะเกิด "จุดที่ไม่เก็บวันนี้แสดงเหมือนเก็บ" ซึ่งเป็นข้อมูลผิดต่อประชาชน · บรรเทาด้วยการไล่แก้ตามรายการ 7 ข้อข้างบนและมีเทสครอบทั้งสามสถานะ
3. **ข้อมูลคนขับหลุดออก API สาธารณะ** — บรรเทาด้วยการตรวจจุดส่งออกทุกจุดก่อนเพิ่มฟิลด์ และ `trucks.local.json` ถูก gitignore
