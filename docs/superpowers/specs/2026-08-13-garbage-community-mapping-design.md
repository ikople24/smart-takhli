# ระบบตารางเก็บขยะ — ผูกจุดเก็บกับชุมชน (M8) · Design Spec

**วันที่:** 2026-08-13
**ต่อจาก:** M1–M3 (#116) · M4–M5 (#118) · M6 (#119) · M7 (#120) — ทั้งสี่ PR ยังไม่ merge
**Branch:** `feat/garbage-community` แตกจาก `feat/garbage-real-schedule` (stacked ชั้นที่ 5)

## ปัญหา

M7 นำตารางจริงเข้าระบบแล้ว แต่ตารางฉบับจริงจากกองสาธารณสุข**ไม่มีคอลัมน์ชุมชน** มีแต่ชื่อถนน/ซอย/หมู่บ้าน ผลคือ `communityNames` และ `communityWindows` ของทุกสายว่างเปล่า → **ค้นด้วยชื่อชุมชนไม่เจอ** ทั้งที่เป็นวิธีที่ชาวบ้านจำนวนมากใช้ระบุที่อยู่ตัวเอง

## แหล่งความจริงของชื่อชุมชน

**`geojsonfeatures` เป็นหลัก** (ยืนยันโดยเจ้าของโปรเจกต์: "โปสเตอร์อาจจะเขียนผิด อันนี้ของจริง ใช้ geojson เป็นหลัก")

- 22 เอกสาร แต่ละตัวมี `name` (ชื่อชุมชน), `geometry` (Polygon), `properties.boundaryor` = "เทศบาลเมืองตาคลี", `active: true`
- **`appId: "app_b"` — ใช้ร่วมกับแอปพี่น้อง โมดูลขยะต้องอ่านอย่างเดียว ห้ามเขียน ห้ามลบ** (บทเรียนเดียวกับ Cloudinary ที่แชร์ข้ามแอป)
- ไม่มี 2dsphere index แต่ `$geoIntersects` ไม่ต้องใช้ index (ทำ collection scan) — 22 เอกสารจึงเร็วพอ **อย่าไปสร้าง index บน collection ของแอปอื่น**

`garbage_communities` (21 ชุมชนที่ seed มาจากโปสเตอร์ตอน M1) **ล้างทิ้งแล้ว** ตามคำสั่งเจ้าของโปรเจกต์ ("โปสเตอร์อาจจะเขียนผิด") — เทียบแล้วต่างจากตัวจริงสองจุด: `ชุมชนหัวเขา` (ชื่อคลาดของ `หัวเขาตาคลี`) และขาด `พุทธนิมิต` ไปทั้งชุมชน · ตรวจก่อนลบว่าไม่มีโค้ดไหนอ่าน collection นี้ (มีแต่ accessor กับ index ที่ประกาศทิ้งไว้ใน `lib/garbage/db.ts`)

**สถานะข้อมูลจากโปสเตอร์ ณ ตอนนี้ — ล้างครบแล้ว:** งานมอบหมายถูก `deleteMany` แล้วเขียนใหม่จากไฟล์ชีตตอน M7 (56 งาน) · สายและจุดเก็บถูกทับด้วยข้อมูลชีต (`source` ชี้ไฟล์ชีต, `needsVerification` เป็น false) · `communityNames`/`communityWindows` ว่างทั้งหมด 0 รายการ · `garbage_communities` ลบแล้ว 21 รายการ

**สิ่งที่ยังเหลือในรีโปแต่ไม่ได้ใช้แล้ว:** `data/garbage/schedule-seed.json` และ `scripts/seed-garbage.mjs` — เก็บไว้เป็นประวัติ **ห้ามรันทับข้อมูลจริง** (สคริปต์เป็น insert-only อยู่แล้วจึงไม่ทับของเดิม แต่จะ insert ชุมชนจากโปสเตอร์กลับเข้ามาถ้ารัน) · ควรพิจารณาลบทั้งคู่ในรอบทำความสะอาด

## แนวทาง (ตัดสินร่วมกับเจ้าของโปรเจกต์)

**ให้ระบบเติมให้ก่อน แล้วเจ้าหน้าที่ตรวจและเติมส่วนที่เหลือ** — ไม่ใช่อัตโนมัติล้วน และไม่ใช่คนกรอกล้วน

วัดจากข้อมูลจริงแล้ว (ไม่ใช่ประมาณ):

| ขั้น | จำนวน |
|---|---|
| จุดเก็บไม่ซ้ำทั้งหมด | 145 |
| จับคู่ชื่อกับถนนใน `roads` ได้ | 66 (46%) |
| ในนั้น centroid ตกใน polygon ชุมชน | 62 (94% ของที่จับคู่ได้) |
| **เติมอัตโนมัติได้จริง** | **62 จุด (43%)** |
| เหลือให้เจ้าหน้าที่ | ~83 จุด |

จุดที่จับคู่ไม่ได้คือ **โรงเรียน · หมู่บ้านจัดสรร · ตลาด · "หน้าบ้าน…"** ซึ่งไม่ใช่ถนน จึงไม่มีวันอยู่ในชั้นข้อมูลถนน — ต่อให้หาชั้นถนนที่ดีกว่านี้ก็ไม่ช่วย นี่คือเหตุผลที่ทำอัตโนมัติล้วนไม่ได้

เหตุผลที่ไม่ให้คนปักหมุดบนแผนที่แทน: ปักหมุด 83 จุดช้ากว่าเลือกจาก dropdown มาก และเจ้าหน้าที่ที่ขับรถทุกวันรู้คำตอบทันทีโดยไม่ต้องดูแผนที่

## โครงข้อมูล

เพิ่มสองฟิลด์ใน `RouteStop`:

```ts
  /** ชื่อชุมชนที่จุดนี้อยู่ — อ้างชื่อจาก geojsonfeatures.name (ไม่ใช่ garbage_communities) */
  communityName?: string | null;
  /** ที่มาของค่า — "auto" = ระบบเดาจากถนน+polygon, "manual" = เจ้าหน้าที่ยืนยัน/แก้เอง */
  communitySource?: "auto" | "manual" | null;
```

`communitySource` จำเป็นเพราะต้องแยกให้ออกว่าค่าไหน "ระบบเดามาให้ ยังไม่มีคนตรวจ" กับ "คนยืนยันแล้ว" — หน้าแอดมินจะได้ไฮไลต์เฉพาะที่ต้องตรวจ และถ้ารันสคริปต์เติมซ้ำ ต้อง**ไม่ทับค่าที่เป็น manual**

`roadId` ที่ออกแบบไว้ตั้งแต่ M1 แต่ไม่เคยใช้ จะถูกเติมไปพร้อมกันในจุดที่จับคู่ถนนได้ — เป็นบันไดขั้นแรกของงานแผนที่เส้นทางที่อยู่ใน roadmap

**ไม่แตะ `communityNames` / `communityWindows` เดิม** — สองฟิลด์นั้นเป็นของโมเดลเก่าที่ผูกชุมชนกับ *ช่วงเวลาของรถ* ซึ่งข้อมูลจริงไม่มี ปล่อยว่างไว้และค่อยพิจารณาลบในรอบทำความสะอาด

## สคริปต์เติมอัตโนมัติ

`scripts/map-garbage-communities.mjs`

- ไม่ใส่แฟล็ก = dry-run รายงานว่าจะเติมกี่จุด ข้ามกี่จุด และเติมเป็นชุมชนอะไรบ้าง
- `--yes` = เขียนจริง
- **ห้ามทับจุดที่ `communitySource === "manual"`** ไม่ว่ากรณีใด (แม้ใส่ `--force`) — งานที่เจ้าหน้าที่ยืนยันแล้วต้องชนะเสมอ
- ขั้นตอนต่อจุด: normalize ชื่อจุด → หาถนนใน `roads` (ใช้ `name` และ `aliases` แบบเดียวกับที่ `search.ts` ทำ) → เอา `centroid` ยิง `$geoIntersects` กับ `geojsonfeatures` → ได้ชื่อชุมชน → เขียน `communityName`, `communitySource: "auto"`, `roadId`
- จุดที่หาถนนไม่เจอ หรือ centroid ไม่ตกใน polygon ไหนเลย → ปล่อยว่าง รายงานเป็นรายการให้เจ้าหน้าที่ไล่เติม
- เขียน audit log หนึ่งรายการสรุป (`garbage_communities_mapped`)

**ข้อจำกัดที่ยอมรับ:** ใช้ centroid ของถนนทั้งเส้น ถนนสายยาวที่พาดผ่านหลายชุมชนจะได้ชุมชนที่ centroid ตกอยู่เท่านั้น ซึ่งอาจไม่ตรงกับจุดที่รถจอดจริง — นี่คือเหตุผลหนึ่งที่ต้องให้เจ้าหน้าที่ตรวจ ไม่ใช่เชื่อค่าอัตโนมัติ 100%

## API

- `GET /api/garbage/communities` — **ต้องล็อกอิน** คืนรายชื่อ 22 ชุมชนจาก `geojsonfeatures` (เฉพาะ `name` เรียงตามชื่อ) สำหรับเติม dropdown ในหน้าแอดมิน · ไม่ส่ง geometry ออก (ไม่จำเป็นและ payload ใหญ่)
- `PUT /api/garbage/routes/[code]` — `stopDraftSchema` รับ `communityName` เพิ่ม · เมื่อเจ้าหน้าที่บันทึกค่าจากฟอร์ม ให้ตั้ง `communitySource: "manual"` เสมอ (การกดบันทึกคือการยืนยัน) · ต้อง validate ว่าชื่อชุมชนที่ส่งมาอยู่ใน 22 ชื่อจริง ไม่งั้นพิมพ์ผิดแล้วค้นไม่เจอตลอดไป

## UI

**หน้าแอดมิน — `RouteManagerModal`** (ซึ่งแก้รายการจุดอยู่แล้ว): แต่ละแถวจุดเพิ่ม dropdown ชุมชน · จุดที่ยังว่างและจุดที่เป็น `auto` แสดงต่างกันให้เห็นชัดว่าอันไหนต้องตรวจ · มีตัวนับด้านบนว่า "ยืนยันแล้ว X / ทั้งหมด Y จุด" เพื่อให้เห็นความคืบหน้า

**หน้าประชาชน:** ค้นด้วยชื่อชุมชนกลับมาใช้ได้ โดย `search.ts` จับคู่ `stop.communityName` แทนการวนอ่าน `communityWindows` แบบเดิม · ผลลัพธ์ของ `matchType: "community"` ให้แสดงชื่อจุดจริงด้วย ("ชุมชนมาลัย · ถนนดอกไม้แดง") เพราะชาวบ้านต้องรู้ว่าจุดไหนในชุมชนตัวเอง ไม่ใช่แค่ว่าชุมชนถูกเก็บ

## การทดสอบ

**เทสอัตโนมัติ** — `lib/garbage/community.ts` แยกส่วน pure ออกมาเทส: การ normalize ชื่อเพื่อจับคู่ถนน (ต้องใช้กฎเดียวกับ `search.ts` ไม่งั้นจับคู่ได้คนละแบบ) และการเลือกชุมชนเมื่อ polygon ซ้อนกันหลายอัน (เลือกอันแรกแบบกำหนดแน่นอน ไม่ใช่สุ่มตามลำดับที่ DB คืนมา)

**ตรวจกับข้อมูลจริง:** dry-run ต้องได้ 62 จุด · ถนนดอกไม้แดง → ชุมชนมาลัย · ถนนเจ้าเงาะ → ชุมชนเขาใบไม้ · หลังเขียนจริง ค้น "มาลัย" ต้องเจอทั้งชื่อถนนและชื่อชุมชน · รันสคริปต์ซ้ำต้องไม่ทับค่า manual

**เกตปิดท้าย:** `npm test && npx tsc --noEmit && npm run lint && npm run build`

## ความเสี่ยง

1. **แตะ collection ของแอปอื่น** — บรรเทาด้วยการอ่านอย่างเดียวเท่านั้น ไม่สร้าง index ไม่เขียน ไม่ลบ และเขียนกำกับไว้ในเอกสารโมดูล
2. **ค่าอัตโนมัติผิดแล้วไม่มีใครตรวจ** — บรรเทาด้วย `communitySource` ที่ทำให้หน้าแอดมินไฮไลต์ของที่ยังไม่ยืนยัน และตัวนับความคืบหน้า
3. **ชื่อชุมชนพิมพ์ผิดจากฟอร์ม** — บรรเทาด้วยการ validate กับ 22 ชื่อจริงฝั่งเซิร์ฟเวอร์ ไม่ใช่รับอะไรก็ได้
